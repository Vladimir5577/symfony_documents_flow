## 2. Целы ли защиты БД (без них ledger-инварианты держатся только на коде)

Прислать вывод целиком:

```sql
-- 2.1. CHECK-констрейнты: их 8+ по спеке, они последняя защита от отрицательного остатка
SELECT conrelid::regclass AS tbl, conname, pg_get_constraintdef(oid)
FROM pg_constraint
WHERE contype = 'c' AND conrelid::regclass::text LIKE 'inventory%'
ORDER BY 1, 2;

-- 2.2. Главный арбитр UPSERT остатков. ОБЯЗАН быть UNIQUE NULLS NOT DISTINCT.
-- Если он обычный UNIQUE — остатки будут молча задваиваться, а не накапливаться.
SELECT conname, pg_get_constraintdef(oid)
FROM pg_constraint
WHERE conname = 'uniq_inv_stock_key';

-- 2.3. Расширение для поиска по номенклатуре
SELECT extname FROM pg_extension WHERE extname = 'pg_trgm';

-- 2.4. Тип ip_address: по спеке INET
SELECT column_name, data_type FROM information_schema.columns
WHERE table_name = 'inventory_device' AND column_name = 'ip_address';
```

**Почему это важно.** Код в `StockPostingService` делает
`ON CONFLICT ON CONSTRAINT uniq_inv_stock_key`. Если констрейнта с таким именем нет
(например, схему накатывали `doctrine:schema:update`, который его не создаёт), то **каждое
проведение документа падает с SQLSTATE 42704**. Если он есть, но без `NULLS NOT DISTINCT` —
хуже: ошибки не будет, а остатки начнут плодить дубли строк, и разойдётся это не сразу.

## 7. Версия конверта шифрования доступов

Переход с libsodium на OpenSSL AES-256-GCM принят — `ext-sodium` не требуется, вопрос не в этом.

Вопрос в версии. Формат конверта изменился:

| | было (secretbox) | стало (GCM) |
|---|---|---|
| раскладка | `nonce(24) ‖ cipher` | `nonce(12) ‖ tag(16) ‖ cipher` |
| префикс | `v1:` | **`v1:`** |

`CURRENT_KEY_VERSION` остался `1`, хотя сам класс документирует механизм: «Ротация: новый ключ =
новая версия; decrypt выбирает ключ по префиксу версии». Сейчас `v1:` означает два несовместимых
формата, и старая запись при расшифровке даст «wrong key or tampered data» — то есть будет
выглядеть как взлом или потеря ключа, а не как смена формата.

7.1. Сохранялись ли хоть раз доступы устройств на проде до этой правки?
```sql
SELECT COUNT(*), MIN(created_at), MAX(created_at) FROM inventory_device_credential;
SELECT DISTINCT left(secret_cipher, 3) FROM inventory_device_credential;
```
     Если таблица пуста — вопрос закрыт, делать ничего не надо.

7.2. Если записи есть — расшифровать их уже нечем, и правильнее не чинить задним числом,
     а поднять `CURRENT_KEY_VERSION` до `2` и завести доступы заново. Тогда следующая смена
     формата не создаст той же двусмысленности.

7.3. Мелочь оттуда же: `sodium_memzero($plain)` заменён на `$plain = str_repeat("\0", strlen($plain))`.
     Это не затирает исходную память, а только переприсваивает переменную — прежняя строка
     остаётся в куче до сборки мусора. Не критично, но и не эквивалент: если затирающий аналог
     нужен, в OpenSSL-ветке его нет, и честнее убрать строку, чем считать её защитой.
